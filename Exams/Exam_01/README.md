## Задача 1: (150 точки)

Определете сложността откъм **време и памет** в най-лошия случай на всеки един от дадените фрагменти. **ЗАДЪЛЖИТЕЛНО** обосновете отговора си в рамките на 2-3 изречения.

---

### 1.1)

**C++:**

```cpp
void f1(int n) {
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j += (n + 1) / 2) {
            cout << i;
        }
    }
}
```

**Python:**

```python
def f1(n):
    for i in range(n):
        for j in range(0, n, (n + 1) // 2):
            pass
```

*Отговор:* $O(N)$ време, $O(1)$ памет
Стъпката на вътрешния цикъл е $\lceil N/2 \rceil$, така че той се изпълнява най-много 2 пъти ($j = 0$ и $j = \lceil N/2 \rceil$). Външният цикъл се изпълнява $N$ пъти, следователно общо $O(2 \cdot N) = O(N)$.

### 1.2)

**C++:**

```cpp
void f2(const std::vector<int>& a, int k) {
    int n = a.size();
    int j = 0;
    std::vector<int> result;
    for (int i = 0; i < n; i++) {
        while (j < i) {
            result.push_back(a[j]);
            j++;
        }
    }
}
```

**Python:**

```python
def f2(a, k):
    n = len(a)
    j = 0
    result = []
    for i in range(n):
        while j < i:
            result.append(a[j])
            j += 1
```

*Отговор:* $O(N)$ време, $O(N)$ памет
Променливата $j$ не се нулира и само расте, така че вътрешният цикъл прави общо най-много $N - 1$ итерации за **цялото** изпълнение на функцията (амортизирано $O(1)$ на итерация на външния цикъл). В `result` се добавят $N - 1$ елемента, затова паметта е $O(N)$. Параметърът $k$ не се използва.

### 1.3)

**C++:**

```cpp
void f3(int n) {
    if (n == 0) {
        return;
    }
    for (int i = 0; i < n; i++) {
        f3(n - 1);
    }
}
```

**Python:**

```python
def f3(n):
    if n == 0:
        return

    for i in range(n):
        f3(n - 1)
```

*Отговор:* $O(N!)$ време, $O(N)$ памет

Абсолютно коректното решение (което не изискваме!):

$T(N) = N \cdot T(N - 1) + O(N)$: на ниво $N$ има 1 извикване, на ниво $N - 1$ има $N$ извиквания, на ниво $N - 2$ има $N(N-1)$ и т.н., общо $\sum_{k=0}^{N} \frac{N!}{k!} \le e \cdot N! = O(N!)$. Дълбочината на рекурсията е $N$, затова паметта е $O(N)$.

**За максимум точки е достатъчно да покажете по някакъв начин, че времевата сложност е $O(N!)$, без да се налага да извеждате точната формула.**

### 1.4)

**C++:**

```cpp
// matrix има N реда и M колони
void f4(std::vector<std::vector<int>>& matrix) {
    for (auto& row : matrix) {
        std::sort(row.begin(), row.end());
    }
}
```

**Python:**

```python
# matrix има N реда и M колони
def f4(matrix):
    for row in matrix:
        row.sort()
```

*Отговор:* $O(N \cdot M \cdot \log M)$ време, $O(\log M)$ допълнителна памет за C++ / $O(M)$ за Python
Сортираме всеки от $N$-те реда с дължина $M$, като всяко сортиране е $O(M \log M)$. `std::sort` (introsort) сортира на място и използва $O(\log M)$ памет за рекурсията, а `list.sort()` в Python (Timsort) използва до $O(M)$ допълнителна памет.

### 1.5)

**C++:**

```cpp
int f5(int n) {
    if (n <= 1) {
        return n;
    }
    while (n % 2 != 0) {
        n--;
    }
    return f5(n / 2);
}
```

**Python:**

```python
def f5(n):
    if n <= 1:
        return n

    while n % 2 != 0:
        n -= 1

    return f5(n // 2)
```

*Отговор:* $O(\log N)$ време, $O(\log N)$ памет
`while` цикълът се изпълнява най-много веднъж (ако $n$ е нечетно, $n - 1$ е четно), т.е. $O(1)$. След това $n$ се дели на 2, така че рекурсията има дълбочина $\log N$.

Допуска се и отговор $O(1)$ памет с аргументация за опашкова рекурсия.

### 1.6)

**C++:**

```cpp
void f6(int n) {
    if (n <= 0) {
        return;
    }
    for (int i = 0; i < n; i++) { cout << i; }
    f6(n - 1);
}
```

**Python:**

```python
def f6(n):
    if n <= 0:
        return

    for i in range(n):
        pass

    f6(n - 1)
```

*Отговор:* $O(N^2)$ време, $O(N)$ памет
На всяко ниво се изпълнява цикъл с $n$ итерации, общо $N + (N - 1) + \dots + 1 = \frac{N(N+1)}{2} = O(N^2)$. Дълбочината на рекурсията е $N$, затова паметта е $O(N)$.

Допуска се и отговор $O(1)$ памет с аргументация за опашкова рекурсия.

## Задача 2: (150 точки)

Да се напише програма, която прочита от конзолата ***M* цели положителни числа** – суми на телефонни сметки, и ***N* цели положителни числа** – суми на направени плащания. Всяко плащане със сума ***x*** погасява **точно една** телефонна сметка със сума ***x***. Програмата трябва да отпечата сумите на сметките, които остават **НЕ**платени, сортирани в възходящ ред.

### Вход

- На първия ред ще прочетете числата *M* и *N*, където 1 ≤ *N* < *M* ≤ 1000000.
- На втория ред ще бъдат въведени *M* на брой числа в интервала [1, 1000] – сумите на сметките.
- На третия ред ще бъдат въведени *N* на брой числа в интервала [1, 1000] – сумите на плащанията.

Гарантирано е, че за всяко плащане има неплатена сметка със същата сума. Ако такива сметки са няколко то се погасява една от тях(няма значение коя от тях)

### Изход

- В конзолата трябва да изведете сумите на неплатените сметки в **възходящ ред.**

В рамките на 1-2 изречения обяснете сложността на вашето решение **по време** и **по памет.**

### Примери

**Пример 1**

Вход:

```
7 4
3 7 3 4 10 1 9
10 3 9 4
```

Изход:

```
1 3 7
```

**Пример 2**

Вход:

```
5 2
5 5 5 1 2
5 1
```

Изход:

```
2 5 5
```

**Пример 3**

Вход:

```
4 3
8 6 4 2
2 4 6
```

Изход:

```
8
```

*Обяснение на пример 1:* платени са сметките 10, 3, 9 и 4. Остават 3, 7 и 1, които в сортиран ред са 1 3 7.

> **Важно:** Задачата може да бъде решена по няколко начина с различна сложност. Колкото по-ефективно е решението ви по време, толкова повече точки ще получите. Максималният брой точки се дава само за решение с оптимална сложност и правилна обосновка.

### Решения

Решения може да видите [тук](Solutions/Task2). С $K = 1000$ означаваме максималната сума.

| Решение | Време | Памет |
| --- | --- | --- |
| `quadratic` – за всяко плащане търсим линейно съответна сметка и я премахваме, накрая сортираме | $O(N \cdot M + M \log M)$ | $O(\log M)$ допълнителна памет за `std::sort` / $O(M)$ за Python |
| `nlog` – сортираме сметките и плащанията и ги обхождаме едновременно с два указателя | $O(M \log M + N \log N)$ | $O(\log M + \log N)$ допълнителна памет за `std::sort` / $O(M + N)$ за Python |
| `counting` (оптимално) – броим колко сметки има за всяка сума и изваждаме плащанията | $O(M + N + K) = O(M + N)$ | $O(K) = O(1)$ |

> [!NOTE]
> В сложността по памет **не** броим масивите, в които пазим входните данни (сметките и плащанията) – те са $O(M + N)$ при всяко решение, което ги съхранява. Броим само допълнителната памет, която използва самият алгоритъм.
